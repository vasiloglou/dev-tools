## What was repaired, in `24003fd`

9 files, +409 −216: `skills/components/scripts/components_index.py`, `tests/test_tools.py`,
`skills/components/SKILL.md`, the two built copies of the first and third in `plugins/`, and
dev-tools' own catalog and its generated page.

**F1. Any tracked file that changed hands.** `changed` looked for regrouped files among the
counted modules and the files a `modules:` line names one by one. It now asks git for every
tracked file (`git ls-files -z`) and takes each one that does not differ and that one of the
entry's two `modules:` lines covers and the other does not. A file of any kind counts, as a
file that differs always did.

**F2. One path, one spelling.** `module_paths` reads each path of a `modules:` value through
`posixpath.normpath`: `./src/a.py` and `src/./a//b.py` are `src/a.py` and `src/a/b.py`.
`covers` compares in that spelling, which is the one git reports.

**F3 and F7. Where an entry ends.** One pattern, `ENTRY`, says it: an entry runs from its
`###` heading to the next heading of any level (one to six `#`, then a blank) or the
generated verbs block. `parse_components`, `write` (`rewrite`) and the lines that are no
field all read it, and `entry_commits` stops dating an entry at the same line. Before, the
fields and `write` ran to the next `###`, the other lines stopped at any `#` or `<!--`, and
the blame reader ran to the next `###`. A comment, and a line such as `#ticket`, are now
lines of the entry.

**F4. The bytes at the base.** `files_at` returns bytes. `base_snapshot` still gives the
import graph its text, decoded as UTF-8, and also returns the bytes, which the names lead
parses as `parse_source` reads a file on disk: by its own coding line.

**F5. Names as they are.** `base_snapshot` reads `git diff --name-status` and
`git ls-files --others` with `-z`.

**F6. One reading of "has words".** `entry_commits` dates a dating line when its value has
something left after `strip()`, which is what `answered` asks.

**F8. Keys no field can have.** The two keys the parser adds beside an entry's fields are
`*repeated` and `*rest`. `_repeated`, which was there before this pull request and had the
same fault, is renamed with it.

**F9. The words of a name, on both sides.** `name_words` splits capital humps, and a run of
capitals from the word after it, and is applied to `does` and `verbs` as well as to the
name.
