**F1. What counts as an answer.** `changed` took any difference in `does`, `verbs`, `flow`
or `reread` as an answer. It now asks one function, `answered`: a dating field answers when
it holds words now that it did not hold at the base. A field deleted, left empty or left
with only blanks is no answer, and a line changed only in the blanks around its words is
none either. The line names what happened: `reread: core.sizes (reread removed): ...`, or
`(only notes edited, reread removed)`.

`review` reads the same rule from the other side: `entry_commits` no longer dates an entry
from a dating line with nothing after its colon. Before, an empty `- reread:` line dated the
entry as read on the day the empty line was written.

**F2. Whose code a changed path is.** `changed` matched each changed path against the
catalog as it is now. A path that differs now counts for the component that held it at the
base as well as the one that holds it now. A component the change removed is kept in that
reckoning, so a subsystem that listed it is told. A file that does not differ asks nothing,
as before.
