Component index

A map of what your code already does, that an agent reads before it writes.

An agent starts every session knowing nothing about your codebase. Without a map it writes a second date parser, a third retry helper, a fourth way to format a file size. The component index is that map: searchable by what the code does, and kept honest by a check.

Search by capability

"Is there already something that does this?"

The agent asks in plain words before it plans new code. The answer names the component, the file, and the function to call.

In the phase workflow this is not optional: each plan has a Reuse section that records what was searched for and what was found, and you see it when you approve the plan.

shelf · asking what already existscaptured
$ components search human readable size
component format.sizes: Format a byte count as a short human-readable size such as 1.5 kB (humanize_bytes)
module src/shelf/units.py: Turn byte counts into short text a person can read.
component fs.scan: Walk a folder tree and list every regular file with its size in bytes
module src/shelf/scan.py: Walk a folder and list the regular files in it.
coverage: 4/4 src/shelf modules assigned to components; external: none

$ components search checksum
no component matched: this is not proof that nothing exists; search modules/ and git grep
coverage: 4/4 src/shelf modules assigned to components; external: none

A match names the component and the file. No match says so plainly, and says it is not proof that nothing exists.

Two layers

People write the meaning. The tool writes the details.

The catalog has one short entry per component, written by hand: what it is for, the verbs it covers, which files belong to it.

Everything else is generated from the source: every function with its signature and one-line summary, and which component uses which. The same search can also cover the libraries the project has installed. Generated pages are never edited by hand, so they cannot drift from the code.

shelf · one entry in the catalogcaptured
$ grep -A8 '### report.rows' docs/components/COMPONENTS.md
### report.rows
- does: Order file entries largest first and pair each path with its human-readable size, as rows for a size report
- verbs: sort by size, largest files first, build report rows
- status: canonical
- modules: src/shelf/report.py
- uses: format.sizes, fs.scan
- used_by: (none)
- tests: tests/unit/shelf/test_report.py

The purpose, verbs, files and tests were written by hand. The two lines saying what it uses and what uses it were generated.

Kept honest

It notices when the code moves on

Add a file and the check fails, because the index no longer matches the source. The coverage line then names every file that no component has claimed. Closing a phase includes giving each new file a home, so the map is complete at the start of the next phase.

shelf · a new file appearscaptured
$ git status --short src
?? src/shelf/report.py

$ components --check
stale or missing: docs/components/modules/_root.md
exit code 1

$ components stats
coverage: 4/5 src/shelf modules assigned to components; external: none
src/shelf/report.py

$ components stats
coverage: 5/5 src/shelf modules assigned to components; external: none

The new file makes the index stale, and coverage drops to 4 of 5 with the file named. After it is given a component: 5 of 5.

What it changes in practice

MomentWithout the indexWith it
Scoping a phaseThe agent greps for a few names it guessesIt lists the capabilities needed and looks each one up; you see a table of what exists
Planning"Add a helper to format sizes""Reuse humanize_bytes from the units component"
Changing shared codeCallers found by search, some missedThe component's used by list is the set of callers to keep working
Reaching for a libraryA new dependency, or a hand-written copyThe index of installed libraries shows what is already available
FinishingNew files nobody will find againEach new file is given a component when the phase closes, and the coverage line shows any that were missed

It reads source text only. The index is built by parsing files, never by importing or running your code, so it works on a project that does not currently start.
